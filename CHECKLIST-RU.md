# Проверка локальной синхронизации MT5 — что нужно сделать

> Для второго разработчика. Фаза 39 закрыта, но всё, что требует живого терминала MT5,
> не проверено ни разу — ни у владельца (у него нет MT5, он торгует с телефона), ни в
> песочнице. Это твоя часть.
>
> Технические детали — `agent/README.md`. Здесь только порядок действий.

---

## Что изменилось и зачем

Раньше историю сделок тянул наш сервер на Windows-VPS. Он умер, и мы его не чиним.

Теперь это делает программа на **твоём** компьютере: заходит в твои счета через локально
установленный MT5 и отправляет закрытые сделки в Treedger.

Смысл в том, **откуда идёт логин**. Раньше все счета всех пользователей логинились с
одного адреса нашего сервера — проп-фирмы (FTMO, The5ers, FundedNext, Topstep) считают это
признаком доступа третьих лиц и за такое сносят аккаунт. Теперь в счёт заходит его
владелец со своего адреса, и придраться не к чему.

**Поэтому счета должны быть твои собственные, и вход — с твоего IP.** На чужих счетах
проверка теряет смысл.

---

## Перед началом

**1. MetaTrader 5 на компьютере.** Если его нет — поставь у своего брокера. Без терминала
не проверить ничего.

**2. Войди в терминал инвестор-паролем**, а не обычным. Инвестор-пароль read-only на уровне
брокера: по нему невозможно открыть сделку, даже если программу кто-то подменит. Это
единственная гарантия, которая не зависит от нашего кода.

**3. Обнови репозиторий и поставь зависимости:**

```powershell
cd C:\tradeproof
git pull
pip install -r agent/requirements.txt
```

Больше ничего не нужно: ни ключей, ни переменных окружения, ни настроек. Программа
обращается к боевому `https://treedger.com`, пароли расшифровываются на сервере.

---

## Шаг 1. Ядро — работает ли синхронизация вообще

Это главное. Если не работает, остальное неважно.

**1.1.** Зайди в Treedger своим аккаунтом. Если счёта там нет — добавь: «+ Счёт», номер,
инвестор-пароль, сервер брокера. Сохранится мгновенно, никаких проверок не будет — счёт
проверит программа при первом заходе.

**1.2.** Настройки → вкладка «Аккаунт» → «Привязать программу». Появится короткий код
вида `XYJC4KNL`, он живёт 15 минут и одноразовый.

**1.3.** Запусти программу — **обязательно из папки репозитория**, иначе Python не найдёт
файл:

```powershell
cd C:\tradeproof
python -m agent.main
```

Путь подставь свой, если репозиторий лежит не там. Проверить, что попал куда надо:
`dir agent\main.py` — файл должен найтись.

Именно `python -m agent.main`, а не `python agent/main.py` — при запуске файлом Python не
видит корень проекта и не находит пакет `agent`. В `agent/README.md` пока написан второй,
неработающий вариант.

Откроется окно. PowerShell дальше не нужен — он только для запуска, потому что сборку в
`.exe` мы ещё не делали. У пользователя это будет обычный двойной клик по скачанному
файлу, окно то же самое.

**1.4.** Вставь код в окне. Программа должна показать список твоих счетов.

**1.5.** Нажми «Обновить».

### Что смотреть

- Прошла ли программа по всем счетам подряд, **не требуя переключать счёт в терминале руками**
- Появились ли сделки в журнале на сайте, посчиталась ли статистика
- **Начальный стоп-лосс** — открой сделку, где стоп потом двигался в безубыток. Должен
  отображаться **исходный** стоп, а не перенесённый. Это самое хрупкое место во всей фазе:
  в истории сделок MT5 поля стопа нет вообще, он читается с ордера, открывшего позицию
- Нажми «Обновить» второй раз — **дублей быть не должно**, программа должна отчитаться,
  что новых сделок нет

### Устойчивость

Впиши одному счёту заведомо неверный пароль и запусти. Этот счёт должен показать ошибку,
а остальные — спокойно досинхронизироваться. Сбой одного счёта не должен ронять остальные.

## Шаг 2. Проба кодов ошибок

Это не проверка, а **сбор данных**. Программа сейчас не умеет надёжно отличать «счёт закрыт
брокером» от «неверный пароль»: документация MQL5 и код проекта присваивают одним кодам
противоположные значения. Пока это не выяснено, все спорные случаи трактуются как «ошибка
входа» — то есть программа продолжает пытаться.

```powershell
python agent/probe_mt5.py
```

**Прогони дважды:** один раз с **выключенным** «Алготрейдингом» в терминале, второй — с
**включённым**. Это заодно ответит на вопрос, нужна ли вообще эта галочка для чтения
данных — он висит с самого начала проектирования.

Скрипт попросит намеренно неверные данные. Нужны три случая:

- существующий счёт, **неверный пароль**
- существующий счёт, **неверный сервер**
- **закрытый счёт** — провалённый челлендж, истёкший, после выплаты

**Если закрытого счёта нет — так и напиши.** Не подставляй вместо него другой и не
пропускай молча: именно вокруг этого вопроса построена вся логика, и честное «не было»
полезнее выдуманного результата.

Скрипт нигде не печатает и не сохраняет пароли — вывод можно присылать целиком.

## Шаг 3. Проверка утечек

```powershell
npm run build
npx tsx scratchpad/check-agent-secret-leak.ts
```

Скрипт создаёт временный аккаунт, выпускает код привязки, обменивает его и удаляет за
собой. Проверяет, что ни пароль, ни ключ шифрования никуда не попадают.

Ни разу не запускался end-to-end — писался, когда маршруты ещё не были готовы.

## Что прислать

- Оба вывода пробы — с выключенным и включённым «Алготрейдингом», все пять секций
- Получилось ли привязать программу и увидела ли она счета
- Доехали ли сделки, сошёлся ли начальный стоп
- Что было при повторном запуске
- Что было со счётом с неверным паролем
- Вывод проверки утечек
- Скриншот окна программы

**И главное — любое место, где непонятно, что делать.** Это важнее галочек: если
инструкция непонятна тебе, она будет непонятна и пользователю.

**Пароли не присылай никогда, ни в каком виде.** Если что-то упало из-за пароля, хватит
фразы «упало на входе в счёт».

## Чего в программе нет намеренно

Чтобы не искать и не считать недоделками:

- **Сборки в `.exe`, установщика, подписи** — отдельная работа, будет позже
- **Автозапуска с Windows и работы в трее** — тоже позже
- **Кнопки «Обновить» на сайте** — пока только в самом окне программы
- **Живых открытых позиций** — синхронизируются только закрытые сделки, это осознанное
  решение: журнал переживает задержку, монитор нет

---

## Что программа не может по построению

Проверяется её собственным тестом структуры при каждом прогоне, а не только словами здесь:

- **Не может торговать** — кода отправки ордеров в папке нет вообще
- **Не слушает сеть** — ни одного открытого порта, только исходящие запросы
- **Не обновляет себя** — кода самозамены нет
- **Не хранит пароль на диске** — он живёт в памяти на время одного прогона
- **Не имеет доступа к базе** — ни ключа, ни клиента Postgres, только HTTP к Treedger

Проверить самому:

```powershell
grep -rn "order_send\|order_check" agent/
pytest agent/tests -q
```

Первая команда должна не найти ничего, вторая — пройти целиком.
