# Проверка локальной синхронизации MT5 — что нужно сделать

> Для второго разработчика. Фаза 39 закрыта, но всё, что требует живого терминала MT5,
> не проверено ни разу — ни у владельца (у него нет MT5, он торгует с телефона), ни в
> песочнице. Это твоя часть.
>
> Технические детали — `agent/README.md`. Здесь только порядок действий.

---

## Что изменилось и зачем

Раньше историю сделок тянул наш сервер на Windows-VPS. Он умер, и мы его не чиним.

Теперь это делает программа на **твоём** компьютере: заходит в твои счета через локально
установленный MT5 и отправляет закрытые сделки в Treedger.

Смысл в том, **откуда идёт логин**. Раньше все счета всех пользователей логинились с
одного адреса нашего сервера — проп-фирмы (FTMO, The5ers, FundedNext, Topstep) считают это
признаком доступа третьих лиц и за такое сносят аккаунт. Теперь в счёт заходит его
владелец со своего адреса, и придраться не к чему.

**Поэтому счета должны быть твои собственные, и вход — с твоего IP.** На чужих счетах
проверка теряет смысл.

---

## Перед началом

**1. MetaTrader 5 на компьютере.** Если его нет — поставь у своего брокера. Без терминала
не проверить ничего.

**2. Войди в терминал инвестор-паролем**, а не обычным. Инвестор-пароль read-only на уровне
брокера: по нему невозможно открыть сделку, даже если программу кто-то подменит. Это
единственная гарантия, которая не зависит от нашего кода.

**3. Обнови репозиторий и поставь зависимости:**

```powershell
cd C:\tradeproof
git pull
pip install -r agent/requirements.txt -r agent/requirements-dev.txt
```

Оба файла, а не только первый: `pytest` лежит в `requirements-dev.txt` и намеренно
отсутствует в `requirements.txt` — там перечислено только то, что нужно самой программе
во время работы. Без второго файла `pytest` ниже не запустится.

Больше ничего не нужно: ни ключей, ни переменных окружения, ни настроек. Программа
обращается к боевому `https://treedger.com`, пароли расшифровываются на сервере.

## Шаг 1. Ядро — работает ли синхронизация вообще

Это главное. Если не работает, остальное неважно.

**1.1.** Зайди в Treedger своим аккаунтом. Если счёта там нет — добавь: «+ Счёт», номер,
инвестор-пароль, сервер брокера. Сохранится мгновенно, никаких проверок не будет — счёт
проверит программа при первом заходе.

**1.2.** Настройки → вкладка «Аккаунт» → «Привязать программу». Появится короткий код
вида `XYJC4KNL`, он живёт 15 минут и одноразовый.

**1.3.** Запусти программу — **обязательно из папки репозитория**, иначе Python не найдёт
файл:

```powershell
cd C:\tradeproof
python -m agent.main
```

Путь подставь свой, если репозиторий лежит не там. Проверить, что попал куда надо:
`dir agent\main.py` — файл должен найтись.

Именно `python -m agent.main`, а не `python agent/main.py` — при запуске файлом Python не
видит корень проекта и не находит пакет `agent`. `agent/README.md` теперь
документирует рабочий вариант.

Откроется окно. PowerShell дальше не нужен — он только для запуска, потому что сборку в
`.exe` мы ещё не делали. У пользователя это будет обычный двойной клик по скачанному
файлу, окно то же самое.

**1.4.** Вставь код в окне. Программа должна показать список твоих счетов.

**1.5.** Нажми «Синхронизировать».

Если окно зависло или показало ошибку — нажми «Открыть папку журнала» (внизу окна) и
пришли файл `agent.log`.

### Что смотреть

- Прошла ли программа по всем счетам подряд, **не требуя переключать счёт в терминале руками**
- Появились ли сделки в журнале на сайте, посчиталась ли статистика
- **Начальный стоп-лосс** — открой сделку, где стоп потом двигался в безубыток. Должен
  отображаться **исходный** стоп, а не перенесённый. Это самое хрупкое место во всей фазе:
  в истории сделок MT5 поля стопа нет вообще, он читается с ордера, открывшего позицию
- Нажми «Синхронизировать» второй раз — **дублей быть не должно**, программа должна отчитаться,
  что новых сделок нет

### Устойчивость

Впиши одному счёту заведомо неверный пароль и запусти. Этот счёт должен показать ошибку,
а остальные — спокойно досинхронизироваться. Сбой одного счёта не должен ронять остальные.

## Шаг 2. Проба кодов ошибок

Это не проверка, а **сбор данных**. Программа сейчас не умеет надёжно отличать «счёт закрыт
брокером» от «неверный пароль»: документация MQL5 и код проекта присваивают одним кодам
противоположные значения. Пока это не выяснено, все спорные случаи трактуются как «ошибка
входа» — то есть программа продолжает пытаться.

```powershell
python agent/probe_mt5.py
```

**Прогони дважды:** один раз с **выключенным** «Алготрейдингом» в терминале, второй — с
**включённым**. Вопрос «нужна ли эта галочка» уже закрыт живым прогоном владельца
2026-09-25: без «Алготрейдинга» подключения к терминалу нет совсем — `(-10005, 'IPC
timeout')`, не только чтения истории. Второй прогон всё равно полезен: он покажет, какой
код получит проба на твоей машине.

Скрипт попросит намеренно неверные данные. Нужны три случая:

- существующий счёт, **неверный пароль**
- существующий счёт, **неверный сервер**
- **закрытый счёт** — провалённый челлендж, истёкший, после выплаты

**Если закрытого счёта нет — так и напиши.** Не подставляй вместо него другой и не
пропускай молча: именно вокруг этого вопроса построена вся логика, и честное «не было»
полезнее выдуманного результата.

Скрипт нигде не печатает и не сохраняет пароли — вывод можно присылать целиком.

Скрипт создаёт временный аккаунт, выпускает код привязки, обменивает его и удаляет за

## Шаг 4. Установщик, автозапуск и работа без присмотра

Это проверка собранной программы, а не исходников: всё ниже делается с тем, что скачивает
обычный пользователь. Нужен релиз, в котором уже есть установщик
(`treedger-agent-<версия>-windows-setup.exe`). Записывай всё, что видишь, дословно —
особенно тексты окон Windows.

**4.1.** Скачай программу через treedger.com/download (кнопка скачивания в мастере). Файл
должен называться `…-windows-setup.exe`. В PowerShell выполни
`Get-FileHash <путь к файлу>` и сравни с хешем, который показывает мастер, — должны
совпасть.

**4.2.** Запусти установщик и **запиши точный текст и порядок всех окон Windows**:
SmartScreen (заголовок, текст, какие кнопки — например «Подробнее» → «Выполнить в любом
случае»), затем окно контроля учётных записей (UAC) и его кнопки. Скриншоты — лучше всего.
Это закроет черновые формулировки в мастере на сайте.

**4.3.** Страницы установщика: выбор языка; папка `C:\Program Files\Treedger`; обе галочки
(«Создать значок на Рабочем столе» и «Запускать вместе с Windows…») — **выключены по
умолчанию**. В конце программа запускается сама. Открой Диспетчер задач → «Подробности»,
включи колонку «С повышенными правами» — у `Treedger.exe` должно быть **«Нет»**.

**4.4.** Вставь код привязки при **русской раскладке**: сначала Ctrl+V, потом правой
кнопкой мыши → «Вставить». Оба способа должны вставлять, и ровно один раз.

**4.5.** Выключи «Алготрейдинг» в терминале → «Синхронизировать». Красная строка должна
начинаться с «Включите „Алготрейдинг“…», а не «Не удалось подключиться…». Включи
«Алготрейдинг» → синхронизация проходит.

**4.6.** На сайте отзови привязку программы → в программе «Синхронизировать» → должно
появиться «Токен был отозван…». Привяжи заново — надпись должна **сразу исчезнуть** и не
вернуться после успешной синхронизации.

**4.7.** Полностью закрой терминал (в Диспетчере задач не должно остаться
`terminal64.exe`) → «Синхронизировать». Ожидается строка «Запуск терминала — запущен
свёрнутым», терминал поднимается свёрнутым, фокус остаётся там, где был (окно, в котором ты
работал, не теряет фокус). Запиши, сколько секунд показала строка «Подключение к
терминалу», и пришли строки журнала `connect attempt A` / `connect attempt B`.

**4.8.** Поставь галочку «Запускать вместе с Windows» в окне программы → Диспетчер задач →
«Автозагрузка приложений» — там должен появиться Treedger. Закрой терминал MT5 и программу,
выйди из учётной записи Windows и войди снова. Ожидается: программа в панели задач
**свёрнутой**, примерно через 15 секунд сама начинает синхронизацию, сама запускает
терминал свёрнутым, появляется «Последняя успешная синхронизация». Пришли строки журнала
этого запуска.

**4.9.** В Диспетчере задач → «Автозагрузка приложений» отключи Treedger → перезапусти
программу → галочка «Запускать вместе с Windows» должна быть **снята**.

**4.10.** Не закрывая программу, запусти установщик ещё раз. Он должен попросить закрыть
Treedger. Закрой её — установка продолжается поверх старой версии. После неё привязка
сохранилась (снова вводить код не нужно).

**4.11.** Удали программу через «Программы и компоненты». Проверь: нет папки
`C:\Program Files\Treedger`, нет ярлыков, нет Treedger в «Автозагрузке приложений»; папка
`%APPDATA%\TreedgerAgent` **осталась** (так задумано — там привязка и журнал).

**4.12.** Если **до** установки команда `schtasks /Query /TN TreedgerAgent` находила
задачу (след старого автозапуска), то после установки она должна её больше не находить.

Терминал закрывать или завершать нигде не нужно, кроме подготовки к пунктам 4.7 и 4.8 —
программа сама его никогда не закрывает.

## Что прислать

- Оба вывода пробы — с выключенным и включённым «Алготрейдингом», все пять секций
- Получилось ли привязать программу и увидела ли она счета
- Доехали ли сделки, сошёлся ли начальный стоп
- Что было при повторном запуске
- Что было со счётом с неверным паролем
- Вывод проверки утечек
- Скриншот окна программы
- По Шагу 4: точные тексты и порядок окон SmartScreen/UAC (4.2), секунды подключения и
  строки `connect attempt A/B` при холодном старте терминала (4.7), строки журнала
  запуска после входа в Windows (4.8) и всё, что пошло не так в 4.1–4.12

**И главное — любое место, где непонятно, что делать.** Это важнее галочек: если
инструкция непонятна тебе, она будет непонятна и пользователю.

**Пароли не присылай никогда, ни в каком виде.** Если что-то упало из-за пароля, хватит
фразы «упало на входе в счёт».

## Чего в программе нет намеренно

Чтобы не искать и не считать недоделками:

- **Подписи кода и работы в трее** — отдельная работа, ещё не сделана.
- Установщик теперь есть (Inno Setup, ставит в `C:\Program Files\Treedger`, quick
  260925-qhs), как и сборка в `.exe` — обе собираются через GitHub Actions в отдельном
  публичном репозитории. Шаги 1–3 по-прежнему делаются из исходников
  (`python -m agent.main`, Шаг 1.3); установщик проверяется в Шаге 4.
- Автозапуск с Windows — флажок «Запускать вместе с Windows» в окне программы и такая же
  галочка в установщике (обе выключены по умолчанию). Теперь это запись в реестре
  текущего пользователя, прав администратора не требует; проверяется в Шаге 4.8–4.9. Если
  включишь его вне Шага 4 — не забудь выключить обратно после теста.
- **Кнопки «Обновить» на сайте** — пока только в самом окне программы
- **Живых открытых позиций** — синхронизируются только закрытые сделки, это осознанное
  решение: журнал переживает задержку, монитор нет

## Что программа не может по построению

Проверяется её собственным тестом структуры при каждом прогоне, а не только словами здесь:

- **Не может торговать** — кода отправки ордеров в папке нет вообще
- **Не слушает сеть** — ни одного открытого порта, только исходящие запросы
- **Не обновляет себя** — кода самозамены нет
- **Не хранит пароль на диске** — он живёт в памяти на время одного прогона
- **Не имеет доступа к базе** — ни ключа, ни клиента Postgres, только HTTP к Treedger

Проверить самому:

```powershell
grep -rn "order_send\|order_check" agent/
python -m pytest agent/tests -q
```

Первая команда должна не найти ничего, вторая — пройти целиком.

Набор проходит одинаково и с установленным пакетом MetaTrader5, и без него: ни один тест
не читает, есть ли MT5 на машине, — недоступность всегда подставляется фикстурой. Если
увидишь падения в `test_mt5_bridge.py` с `assert True is False` или с настоящим кодом MT5
вроде `(-10004, 'No IPC connection')` — это не твоя машина и не твоя ошибка, это вернувшийся
дефект самих тестов (упал релизный прогон #2); сообщи, не подгоняй окружение под тесты.
